```typescript
// ============ Phase 2: 实现视频处理 (2周) ============

// 裁剪视频（看起来简单？）
async function trimVideo(file: File, start: number, duration: number) {
  // 1. 读取文件到内存（⚠️ 受浏览器内存限制）
  const data = await file.arrayBuffer();

  // 2. 写入 FFmpeg.wasm 虚拟文件系统
  await ffmpeg.writeFile('input.mp4', new Uint8Array(data));

  // 3. 执行命令（与服务端一样）
  await ffmpeg.exec([
    '-i', 'input.mp4',
    '-ss', start.toString(),
    '-t', duration.toString(),
    'output.mp4'
  ]);

  // 4. 读取输出（⚠️ 又是内存操作）
  const output = await ffmpeg.readFile('output.mp4');

  // 5. 转换为 Blob（才能下载或预览）
  const blob = new Blob([output], { type: 'video/mp4' });

  // 6. 清理虚拟文件系统（避免内存泄漏）
  await ffmpeg.deleteFile('input.mp4');
  await ffmpeg.deleteFile('output.mp4');

  return blob;
}

// ⚠️ 问题：
// - 内存管理复杂（需要手动管理虚拟文件系统）
// - 大文件处理容易崩溃（浏览器内存限制 2-4GB）
// - 性能不可控（取决于用户电脑）
// - 调试困难（在浏览器 Console 看不到详细错误）
```

## 四、成本详细拆解

### 4.1 开发成本（一次性）

#### 服务端渲染
```
开发时间: 2-3 周
工程师成本（按外包价格）:
  - 后端工程师: ¥800/天 × 15 天 = ¥12,000
  - 前端工程师: ¥600/天 × 10 天 = ¥6,000
  - 总计: ¥18,000

  - 2-3 周专注开发
```

#### 客户端渲染
```
开发时间: 1-2 月
工程师成本:
  - 前端工程师（需要高级）: ¥1000/天 × 40 天 = ¥40,000
  - 学习 FFmpeg.wasm 时间: ¥1000/天 × 5 天 = ¥5,000
  - 调试和优化: ¥1000/天 × 10 天 = ¥10,000
  - 总计: ¥55,000

如果是自己开发:
  - 1-2 月（包括学习时间）
  - 大量踩坑和调试
```

**开发成本差距**: 客户端比服务端多 **3 倍**！

2. 渲染缓存: 相同模板不重复渲染
3. 夜间批量处理: 利用低峰期

优化后:
├─ 100 用户:  ¥300/月

#### 客户端渲染

   - "为什么我的电脑渲染这么慢？"
   - "为什么浏览器崩溃了？"
   - "为什么手机不能用？"

3. 维护成本:
   - 浏览器兼容性问题
   - 不同设备的 bug
   - 持续优化性能

## 七、成本权衡建议

### 场景 1: 个人项目/早期创业（预算 <¥5000/月）

**推荐**: 服务端渲染

**理由**:
- 开发快（2-3 周上线）
- 体验好（留存用户）
- 起步成本可控（¥600/月）

**省钱策略**:
```python
# 1. 限流
@limiter.limit("5/hour")  # 每用户每小时 5 次

# 2. 排队
if queue_size > 10:
    return "当前排队人数较多，请稍后再试"

# 3. 夜间批量处理
if is_night_time():
    priority = "low"
```

---

### 场景 2: 有一定预算（¥5000-20000/月）

**推荐**: 服务端渲染 + 优化

**配置**:
- 多台服务器 + 负载均衡
- GPU 加速（选配）
- 任务队列 + 缓存

**用户体验**: ⭐⭐⭐⭐⭐

---

### 场景 3: 预算紧张，用户量大

**推荐**: 混合方案

**实现**:
```
简单编辑 → 客户端预览（免费）

```

**商业模式**:
- 免费用户：客户端预览 + 有限渲染次数
- 付费用户：无限渲染 + 高优先级
