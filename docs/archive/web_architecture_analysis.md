# Web 端视频编辑架构分析

## 核心问题：视频编辑应该在哪里进行？

### 方案对比

```
┌─────────────────────────────────────────────────────────────┐
│                    方案 A: 服务器端渲染                      │
│  用户浏览器 → 编辑操作 → 服务器渲染 → 返回成品视频          │
└─────────────────────────────────────────────────────────────┘

┌─────────────────────────────────────────────────────────────┐
│                    方案 B: 客户端渲染                        │
│  用户浏览器 → 下载素材 → 本地渲染 → 上传/下载成品           │
└─────────────────────────────────────────────────────────────┘

┌─────────────────────────────────────────────────────────────┐
│                    方案 C: 混合方案（推荐）                  │
│  简单编辑 → 客户端实时预览                                  │
│  最终渲染 → 服务器端高质量输出                              │
│  AI 功能 → 服务器端处理                                     │
└─────────────────────────────────────────────────────────────┘
```

## 一、方案 A: 服务器端渲染（你当前的设计）

### 1.1 架构

```
用户浏览器                         你的服务器
    │                                 │
    ├─ 编辑时间轴（拖拽、设置属性）   │
    │                                 │
    ├─ 点击"渲染" ────────────────→  │
    │                                 ├─ FFmpeg 渲染
    │                                 ├─ MoviePy 合成
    │                                 ├─ Whisper 字幕
    │  等待 2-10 分钟...              │ (CPU/GPU 密集)
    │                                 │
    │  ←────────── 返回视频文件 ──────┤
    │                                 │
    └─ 下载/播放                      │
```

### 1.2 压力分析

#### ✅ 前端压力（很小）
- **CPU**: 几乎无压力（只是 DOM 操作）
- **内存**: < 100MB（只存时间轴 JSON 数据）
- **网络**: 只上传元数据（几 KB），下载成品（几 MB）
- **兼容性**: 任何设备都能用（手机、平板、低端电脑）

#### ⚠️ 后端压力（很大）

**单个视频渲染资源消耗**:
```
CPU:     100% × 核心数（渲染期间）
内存:     2-8 GB（取决于视频分辨率）
时间:     视频时长 × 1-3 倍
磁盘 I/O: 密集（临时文件读写）
GPU:     可选，但需要硬件支持
```

**并发能力**:
```
假设你的服务器: 8 核 CPU, 16GB RAM
├─ 同时渲染 2 个 1080p 视频: OK
├─ 同时渲染 5 个 1080p 视频: 卡顿
└─ 同时渲染 10+ 视频: 崩溃风险
```

**成本估算**:
```
阿里云 ECS (8核16G):  ¥500-800/月
腾讯云 GPU 服务器:     ¥2000-4000/月
AWS EC2 (按需):        $0.5-2/小时
```

### 1.3 适合场景

✅ **你的项目非常适合这个方案**，因为：

1. **已有 AI 视频生成**
   - 你的平台本来就在服务器端生成视频
   - 编辑功能只是 AI 生成后的"微调"
   - 用户已经接受"等待渲染"的流程

2. **专业级输出**
   - AI 生成的视频需要高质量
   - 服务器端可以统一质量标准
   - 可以使用硬件加速（GPU）

3. **统一的工作流**
   ```
   用户输入文本 → AI 生成视频 (服务器) → 后期编辑 (服务器) → 最终视频
   ```
   全程在服务器端，流程一致

4. **用户体验**
   - 不需要下载大文件到本地
   - 不占用用户电脑性能
   - 任何设备都能编辑

## 二、方案 B: 客户端渲染（OpenCut 方式）

### 2.1 架构

```
用户浏览器（强大性能要求）
    │
    ├─ 下载视频素材（可能很大）
    ├─ 使用 FFmpeg.wasm 在浏览器渲染
    ├─ 等待（取决于电脑性能）
    └─ 上传成品或直接下载
```

### 2.2 压力分析

#### ⚠️ 前端压力（很大）
- **CPU**: 100%（用户电脑渲染）
- **内存**: 2-4 GB（浏览器内存限制）
- **网络**: 需要下载所有素材（几百 MB - 几 GB）
- **兼容性**:
  - ❌ 手机/平板几乎无法使用
  - ❌ 低端电脑卡顿
  - ✅ 高端电脑（M1/M2, RTX 显卡）可流畅使用

#### ✅ 后端压力（很小）
- 只存储元数据和文件
- 几乎无计算压力
- 成本极低

### 2.3 适合场景

❌ **不太适合你的项目**，因为：

1. **与 AI 生成流程冲突**
   - AI 生成在服务器 → 视频文件很大 → 下载到浏览器 → 编辑 → 上传？
   - 流程割裂，体验不佳

2. **用户门槛高**
   - 需要高性能电脑
   - 移动端无法使用
   - 等待时间不确定（取决于用户设备）

3. **功能受限**
   - 浏览器的 FFmpeg.wasm 功能有限
   - AI 字幕生成仍需服务器（Whisper 模型太大）
   - 无法使用 GPU 加速

## 三、方案 C: 混合方案（推荐 ⭐）

### 3.1 架构

```
┌──────────────────────────────────────────────────────────┐
│                    前端（浏览器）                         │
│                                                          │
│  ┌────────────────────────────────────────────────┐     │
│  │  轻量编辑 + 实时预览（客户端）                 │     │
│  │  - 拖拽时间轴                                  │     │
│  │  - 调整参数（亮度、音量）                      │     │
│  │  - 实时预览（HTML5 video）                     │     │
│  └────────────────────────────────────────────────┘     │
│                        │                                 │
│                        ▼ 点击"渲染"                      │
└────────────────────────┼──────────────────────────────┘
                         │
                         ▼
┌──────────────────────────────────────────────────────────┐
│                  后端（你的服务器）                       │
│                                                          │
│  ┌────────────────────────────────────────────────┐     │
│  │  高质量渲染（服务器端）                        │     │
│  │  - FFmpeg 专业转码                             │     │
│  │  - MoviePy 复杂合成                            │     │
│  │  - Whisper 字幕生成                            │     │
│  │  - AI 效果增强                                 │     │
│  └────────────────────────────────────────────────┘     │
└──────────────────────────────────────────────────────────┘
```

### 3.2 实现方式

#### 前端: 实时预览（不渲染成品）

```typescript
// frontend/src/components/editor/Preview.tsx

// 使用 HTML5 video 标签预览
// 不需要真正"渲染"，只是播放和可视化

function TimelinePreview({ timeline }) {
  const videoRef = useRef<HTMLVideoElement>(null);

  const handlePreview = () => {
    // 1. 只播放当前选中的视频片段
    const currentElement = timeline.getCurrentElement();

    // 2. 应用滤镜效果（CSS filter）
    videoRef.current.style.filter = `
      brightness(${currentElement.brightness})
      contrast(${currentElement.contrast})
    `;

    // 3. 播放（不需要渲染）
    videoRef.current.play();
  };

  return (
    <div>
      <video ref={videoRef} src={currentVideoUrl} />
      <TextOverlay elements={timeline.textElements} />
    </div>
  );
}
```

**优势**:
- ✅ 实时反馈（毫秒级）
- ✅ 不消耗服务器资源
- ✅ 流畅的编辑体验

**局限**:
- ⚠️ 只是"预览"，不是真正的渲染
- ⚠️ CSS 滤镜效果可能与最终渲染不完全一致

#### 后端: 最终渲染（高质量）

```python
# 用户满意预览效果后，点击"渲染"
# 服务器端使用 FFmpeg + MoviePy 生成最终视频

@router.post("/editor/render")
async def render_final_video(timeline: Timeline):
    # 使用你设计的 TimelineRenderer
    final_video = await timeline_renderer.render(
        timeline,
        quality="high"  # 服务器端高质量渲染
    )
    return {"video_url": final_video}
```

### 3.3 功能分工

| 功能 | 前端（浏览器） | 后端（服务器） | 理由 |
|------|---------------|---------------|------|
| **时间轴编辑** | ✅ | - | 实时交互 |
| **实时预览** | ✅ | - | 毫秒级响应 |
| **拖拽调整** | ✅ | - | 流畅体验 |
| **参数调节** | ✅ | - | 即时反馈 |
| **简单滤镜预览** | ✅ (CSS filter) | - | 快速 |
| **最终渲染** | - | ✅ | 高质量 |
| **字幕生成** | - | ✅ | Whisper 模型大 |
| **AI 增强** | - | ✅ | 需要 GPU |
| **复杂合成** | - | ✅ | 性能要求高 |
| **转场效果** | - | ✅ | 计算密集 |

### 3.4 用户体验流程

```
1. 用户上传/选择 AI 生成的视频
   ↓
2. 在时间轴拖拽、调整参数
   ├→ 实时预览（前端，HTML5 video）
   ├→ 调整满意？ 否 → 继续调整
   └→ 满意 ✅
   ↓
3. 点击"生成高清视频"按钮
   ├→ 提交到服务器渲染队列
   ├→ 显示进度条："排队中... 渲染中 (35%)..."
   └→ 3-5 分钟后完成
   ↓
4. 下载/分享最终视频
```

**用户感知**:
- ✅ 编辑过程流畅（前端实时）
- ✅ 最终质量保证（服务器渲染）
- ✅ 等待时间可接受（因为有"预览"阶段确认效果）
